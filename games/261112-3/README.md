# ピッ！ピッ！ちいさなスーパーの一日 (261112-3)

`format_id: scene3d_life` / `style_id: fable_photoreal` / `subject: no_animal_princess`　識別子: `gf-261112-nx3`

5歳向け・文字なし・指1本・失敗なしの 3D あそび。牛乳2個、りんご2個、いちごパック、長いパンの **同じ6個の実体** が
「朝の陳列 → バーコードでピッ → 袋詰めして渡す → 店じまい」の4場面を通して移動する。

- 遊ぶ: `index.html` を開くだけ (1 ファイル完結。CDN・外部読み込みなし。`file://` と Pages のサブフォルダの両方で動く)
- サムネイル: `thumb.png` (実際のゲーム画面から作成)
- 検証の記録: [`verify/RESULTS.md`](verify/RESULTS.md) (自動生成) と下の「検証」

## 体験の核と因果

品物を棚・かご・袋へドラッグする → 同じ品物が陳列品から会計済みの荷物になり、位置と重さで袋の形や持ち方が変わる
→ 入れる順番や置き場所を変えて、別の形で渡したくなる。

| 操作 (指1本) | 因果 |
|---|---|
| ① 商品を運ぶ | 棚の空きへ「ことん」。傾斜トレーは手前を取ると奥が転がって前へ。かごへ集める・かごごとレジへ運ぶ |
| ② スキャナーをかざす | 近づくと自動で向きが合い、最も近い未読の一品だけを読む。光と「ピッ」が同時。補助店員の手が受け台へ移す |
| ③ 丸ボタンを押す | 全部読んであれば会計確定 (連打しても一度)。未読があれば未読品が手前へ寄るだけ |
| ④ 袋へ出し入れ | 袋は 48 質点の膜 (XPBD)。重さと位置で底のたわみ・持ち手の張り・品物どうしの支え合いが変わる |
| ⑤ 持ち手を引く | 横へ引く=口が開いて届く場所が変わる (離しても開いたまま)。上へ引く=両持ち手をまとめて持ち上げる |
| ⑥ シャッターを動かす | 引いたぶんだけ動き、速さで金属音が変わり、離した位置で止まる |

### 状態遷移

```
朝の陳列(open) --かごを運ぶ(1品以上)--> レジ --全品ピッ+丸ボタン--> 袋詰め --客へ手渡し--> 店じまい(close)
   ^   <--かごを持ち帰る(会計前)--          <--受け台ごと行き来(会計は増えない)-->   |
   |                                                              かごを重ねる → シャッターを下ろす
   +---------------- シャッターを上へ引く = 次の開店(売れた品だけ補充・棚の並びは保持) <-- 店先で「はなまる」
```

- 場面の移動 (空いた所を横になぞる / 見えている棚・レジ・袋台に触れる) だけでは何も巻き戻らず、複製もしない。
- 保存するもの: 品物ごとの所在・列と順番・読取済み/会計済み・袋の中の位置と向き、かご・受け台・持ち手の掛け位置、手渡し状態、シャッター、日数。

### 袋の物理 (`src/bagsim.js`)

- 膜: 6×7 の格子 42 質点 + 持ち手 3 質点×2 = **48 質点**。距離拘束は張力優先 (圧縮にはごく弱くしか抵抗しない=しわになる)。XPBD、1/480 秒刻み。
- 品物: 箱 (牛乳・いちごパック)・球 (りんご)・カプセル (パン) の 2D 剛体。サンプル円 vs SDF の接触 + 摩擦。袋の膜とは外周線分との片側接触。
- 描画: 質点を Catmull-Rom で 23×27 に補間し、品物の厚みに沿って前後の膜をふくらませる。圧縮された所にしわを足す (`src/bagview.js`)。
- 詰め方ごとの固定演出は使っていない。客の持ち直し・添え手・パンをよける構えも、その時の重心・質量・パンの向きから決めている。

## 端末まわり

- Pointer Events、最初に触れた指 1 本 (pointerId) だけを追う。2 本目以降は無視。`pointercancel`・非表示・回転・ウィンドウの blur でつかみを解除し、近い支持面へ置く。
- スクロール・ピンチ・ダブルタップ拡大・長押しメニューを抑止。`viewport-fit=cover` と Safe Area を考慮したカメラ合わせ。縦横どちらでも同じ状態で続く。
- 音は最初のタッチで開始。開始できなくても無音で続行。非表示中は描画・進行・音を止め、復帰直後の大きな時間差は捨てる。
- 負荷: devicePixelRatio は上限 2 (低負荷時 1.5)、ピクセル数上限、fps に応じた動的解像度 (0.5〜1.0)、それでも遅ければ低負荷モード (日ざしの影を止める・影の更新を間引く・ほこりの粒を 44→14 個に)。
  遅い端末でも遊びの速さは実時間に合わせる (1 フレームに最大 4 回まで論理を進める)。
- WebGL の生成失敗、または喪失から約 4 秒復旧しないときは、埋め込みの静止画に切り替える。

### 検証していないこと・限界 (正直な記録)

- **実機 iPad では未検証**。すべてヘッドレス Chromium + SwiftShader (GPU なしの CPU 描画) での結果。iPad での 30fps は未確認。
- ヘッドレスの CPU 描画が非常に遅いため、操作の検証は描画解像度だけを下げた低負荷モード (`?low=1&rs=0.25&fixed=1`) で行い、
  スクリーンショットは同じ保存データを標準画質 (`?fixed=1`) で開き直して撮影した。標準画質のまま通しで遊ぶ検証はしていない。
- 非表示/復帰は `document.hidden` を差し替えて `visibilitychange` を送る方法で確かめた (実際のタブ切り替えではない)。Safe Area は実機のノッチでは未確認。
- 音は「AudioContext が動き、合成音の発音回数が増える」ことまでの確認で、耳で聞いた音質の確認ではない。
- 袋の中の収まり方は物理しだいで幅がある。検証スクリプトの発見4・5 は、狙いの配置になるまで数回やり直すことがある (回数は結果に記録)。
- 見た目は手続き生成の写実寄り 3D で、「現実と見間違う」水準には届いていない (特に人物と通りの背景)。
